## How to regenerate the inventory

`node scripts/build-audit-inventory.mjs` prints the table to **stdout**; it
writes nothing and it knows nothing about statuses. It is a reporting tool, not
a round-trip.

- Columns 1–6 and 8 — `#`, `batch`, `component`, `source path`,
  `public exports`, `specimen route`, `dependencies` — are what it produces.
- Column 7 (`applicable states`), the nine status columns and `evidence` are
  hand-authored and live only in this file.

So when a module is added, renamed or removed: run the generator into a scratch
file, diff it against the table below, and **merge the changed rows by hand**.
Pasting its output over this table replaces every status with `pending`.

`--json` emits the same rows as JSON if you would rather script the merge.

## The nine axes

| Axis | The claim it makes |
|---|---|
| `source` | Tokens only, no retired type role, no fixed height where a minimum is meant, structure matches the contract in RULES §5. |
| `interaction` | The keyboard and pointer path was **run**, not read: tab order, activation keys, arrow keys, disabled inertness. |
| `accessibility` | Accessible name, ARIA state, `aria-invalid` + described error, hit target, and axe clean on every applicable state. |
| `responsive` | 375 / 768 / 1440 checked; nothing overflows horizontally; rows wrap or scroll. |
| `motion` | Motion comes from the named utilities, and reduced motion preserves both the information and the final state. |
| `docs` | Every applicable state is live on the owning specimen with the real component, plus API and rules. |
| `tests` | A behaviour test exists that drives the real public API and would fail if the contract broke. |
| `visual` | The rendered output was **looked at or measured**, in both themes and at the narrow viewport — never inferred from source. |
| `release` | All eight above are `complete` or a written `N/A`. Nothing else. |

## Status vocabulary

- **`pending`** — not audited yet. The starting value for every row.
- **`complete`** — audited, corrected where needed, and evidenced in the last column.
- **`typography complete`** — the type roles were migrated and nothing else was
  audited. It is deliberately not `complete`, and it can never satisfy `release`.
- **`N/A(reason)`** — the axis does not apply, and the reason says why. A written
  N/A counts toward `release`; a blank cell never does.
- **`blocked(reason)`** — a real defect or decision is in the way, named in the
  cell. A `blocked` row can never be `release`.

**A row becomes `release` only when the other eight axes are all `complete` or a
written `N/A`.** Typography-only work is `typography complete`, never `complete`.

**`blocked` is for an owner decision or a defect that cannot be closed from
inside the batch.** It is never a place to park work the auditor could have
finished. If a part is missing from a specimen, document the part.

### What `docs` requires, and what it does not

`docs` asks whether every part a *user of the component* has to choose is live
on the specimen with the real component. **Plumbing does not count**: `*Portal`,
`*Overlay` and `*Anchor` render no UI, carry no state a caller picks between,
and exist because the primitive needs somewhere to hang the tree. Requiring a
specimen for `DialogPortal` and not for `DrawerPortal` was an inconsistency in
the first pass of batch 2, and it blocked one row while leaving two identical
ones `release`.

Everything a caller can see or operate does count — items, labels, groups,
checkbox and radio items, submenus, close buttons, size and variant props.

## Cross-batch findings raised while auditing batch 1

These are defects found in modules this batch does not own. They are recorded
here rather than fixed, so the owning batch inherits them with the evidence.

- **`components/ui/icon.tsx` (batch 4) silently swallows every prop it does not
  destructure.** `Icon` takes `{icon, size, tone, label, className}` and spreads
  nothing, so `data-slot`, `role`, `id`, `aria-*` and event handlers written on
  an `<Icon>` never reach the glyph. It is currently harmless — the call sites
  passing extras are passing `aria-hidden`, which `Icon` already sets — but it
  is dead API that reads as live.
- **`components/ui/spinner.tsx` (batch 3) is the first victim of that.** It
  writes `data-slot="spinner"`, `role="status"` and `aria-label="Loading"` onto
  `Icon`, and all three are dropped. Nothing styles `[data-slot=spinner]` today,
  and a spinner inside a `Button loading` is decoration next to the button's own
  `aria-busy`, so no state is currently unannounced — but the file claims an
  announcement it does not make.
